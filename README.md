# Digit Recognizer

ДЗ1 курса «Исследования и разработка в ML».
Весь ход исследования с кодом, таблицами, графиками и выводами — в **[baseline.ipynb](baseline.ipynb)**.

## Запуск

Python 3.12; зависимости: `pip install -r requirements.txt`.
[Kaggle train.csv](https://www.kaggle.com/c/digit-recognizer/data) положить в `data/raw/`.
Открыть `baseline.ipynb` и выполнить **Restart Kernel → Run All**.
Параметры — в [baseline.toml](baseline.toml). Автоматический запуск того же ноутбука: `python run.py`.

## 1. Постановка и гипотеза

Определяем цифру на одном изображении рукописного символа.
Практический смысл — учебный прототип компонента OCR для цифровых символов.
Распознавание фотографий документов, строк цифр и неизвестных символов здесь не проверяется.

**Цель проекта:** повысить качество распознавания и понять, какие изменения исправляют ошибки модели.

**Исследовательская гипотеза:** обучение нелинейным сочетаниям штрихов уменьшит ошибки
по сравнению с линейной моделью по пикселям. Первая проверка — MLP на тех же данных и split;
затем можно проверить пользу двумерной структуры в CNN.

В ДЗ1 фиксируем логрег как исходный baseline. Сравнение с самым частым классом —
контрольная проверка, а не подтверждение исследовательской гипотезы.
Нейросети пока не обучены; гипотеза о них остаётся непроверенной.

## 2. Формализация

- Задача — многоклассовая классификация цифр 0–9.
- Объект наблюдения и единица предсказания — одно изображение 28 × 28.
- `X` — 784 значения `pixel0`–`pixel783`, целые числа 0–255.
- `y` — столбец `label`, одна цифра 0–9.
- На inference доступны только пиксели; метка в признаки не входит.

## 3. Данные и EDA

Источник — официальные CSV Kaggle Digit Recognizer на основе MNIST.
В контрольном файле 42 000 размеченных изображений, пропусков и точных дубликатов нет.
В классах от 3 795 до 4 684 объектов, сильного дисбаланса нет.

В ноутбуке проверяются схема, целочисленность, диапазоны, пропуски и одинаковые изображения,
в том числе случаи с разными метками. Распределение классов и примеры для EDA строятся по train.
Потенциальный шум — неразборчивые символы, похожие начертания и ошибки разметки.

## 4. Baseline

Контрольная модель — `DummyClassifier(strategy="most_frequent")`, обученная на train.
Основной baseline — логистическая регрессия по пикселям с L2-регуляризацией:
деление пикселей на 255, `C=1`, `solver="lbfgs"`, `tol=1e-4`, `max_iter=1000`.
Параметры зафиксированы заранее, сходимость проверяется. Для деления на константу статистики данных не нужны.

Это простая CPU-модель без аугментаций и ансамблей: удобная отправная точка для последующих улучшений.
Её ограничение — линейные границы в пространстве пикселей.

## 5. Протокол оценки

Основная метрика — **accuracy**, доля верных предсказаний, как в соревновании.
Дополнительная метрика — macro-F1, среднее F1 по десяти цифрам.
Для диагностики считаются precision/recall/F1 отдельно по цифрам и матрица ошибок.
Проверка распределения классов обосновывает использование accuracy.

Разбиение: 80% train / 20% validation, стратификация по классу, seed=42.
При наличии точных дубликатов используется первый из пяти fold `StratifiedGroupKFold`:
одинаковые изображения группируются по пикселям без учёта метки и остаются вместе.
В контрольном файле дубликатов нет, поэтому выбран `train_test_split` со стратификацией.

Модель обучается только на train. Оба baseline используют одинаковые строки.
Ключевые риски утечки — копии изображений в обеих частях, включение метки в признаки,
обучение преобразований на validation и выбор модели по Kaggle test.
В текущем решении эти действия исключены проверками и протоколом.
Схема и точные дубликаты проверяются на всём размеченном файле для формирования split.

В ДЗ1 оценивается заранее выбранная модель. Будущие модели сравниваются по локальной validation accuracy
на неизменном split; test/public leaderboard не используются для выбора.
Один holdout не оценивает разброс качества. Идентификаторов авторов нет, поэтому независимость по почеркам
не гарантируется. Близкие, но не идентичные копии автоматически не обнаруживаются.

## 6. Контрольный результат

33 600 изображений для обучения, 8 400 для валидации:

| Модель | Accuracy | Macro-F1 |
|---|---:|---:|
| Самый частый класс (1) | 0.111548 | 0.020071 |
| Логистическая регрессия | **0.913333** | **0.912139** |

Верно распознаны **7 672 из 8 400** цифр, прирост над dummy — **80,18 процентного пункта**.
Оптимизатор сошёлся за 231 итерацию. Mean ± std и статистическая значимость не оценивались.

Чаще всего модель путает 4 → 9 (41 случай), 3 → 5 (34) и 5 → 3 (32).
В ноутбуке приведены матрица ошибок, галерея и разбор трёх изображений:
row 250 — открытая верхняя часть четвёрки; row 6615 — тройка, ошибочно распознанная как пятёрка
с вероятностью около 0,99; row 5931 — пятёрка с округлой нижней частью, распознанная как тройка.
Возможные причины по форме штрихов — гипотезы, а не доказанные результаты абляций.

Ноутбук выполнен с нуля в новом ядре. При переносе accuracy сохранилась, split и предсказания совпали
с предыдущим baseline побайтно. Машиночитаемые результаты — в `reports/`:
`metrics.json`, `split.csv`, `validation_predictions.csv`, `run.json`.
Последний файл фиксирует данные, конфиг и время обучения.
Между разными платформами и версиями BLAS побитовая идентичность обучения не гарантируется.

## 7. Выводы и исследовательские вопросы

Получен исходный результат: 91,33% accuracy. Основные направления ошибок — 4 → 9 и 3 ↔ 5.
Это база для сравнения улучшений. По текущему запуску нельзя судить о пользе нейросетей:
сравнительные эксперименты ещё не выполнены.

1. **Нелинейность:** даст ли MLP с одним скрытым слоем и ReLU прирост относительно логрега?
   Сравнить accuracy, исправленные и новые ошибки на том же split.
   Результат покажет пользу MLP, но не отделит её от изменения числа параметров и оптимизации.
2. **Пространственная структура:** улучшит ли небольшая CNN качество относительно MLP при близком
   числе параметров и одинаковом числе обработанных обучающих примеров?
   Сравнить accuracy и ошибки по цифрам, зафиксировать время и различия обучения.
3. **Устойчивость:** улучшат ли train-only сдвиги на ±2 пикселя качество одной и той же CNN
   на сдвинутых цифрах? При одинаковом числе шагов сравнить обе версии на исходной validation
   и на одинаковых заранее заданных сдвигах без переноса пикселей через край.
   Это покажет пользу аугментации для устойчивости и возможную цену в исходной accuracy.

Эти вопросы задают следующие эксперименты, а не описывают
уже полученные результаты. Ограничения baseline: один holdout, неизвестные авторы,
отсутствие проверки внешних данных, близких копий и калибровки вероятностей.
